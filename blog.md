# Teaching a frozen LLM new words: experiments in neologism learning

*What happens when you freeze an entire language model and let it learn exactly
one new word? This is a write-up of a series of experiments reproducing and
extending John Hewitt's [neologism learning](https://www.cs.columbia.edu/~johnhew//neologism-learning.html)
([Hewitt et al., 2025](https://arxiv.org/abs/2510.08506)) — including a new,
dead-simple training objective and two findings about where the learned word's
power actually lives.*

---

## The idea in one paragraph

Take a fully trained, **frozen** language model. Add **one new token** to its
vocabulary — a "neologism", written here with a leading `~`, e.g. `~Tothinking`.
Give that token a fresh embedding row and train **only that single row** (a few
thousand floats) on examples that exhibit some behavior. Everything else in the
model — billions of parameters — stays bit-for-bit identical. The new word then
acts as a steering handle: drop it into a prompt and the model exhibits the
behavior. The token is masked out of the output distribution, so it can be *read*
but never *written*.

That's it. No LoRA, no fine-tuning of attention, no RLHF. One embedding row.

The headline result is that this works, and the surprising one is that the
otherwise-unchanged model can **self-verbalize** — describe in plain English what
the new word means to it — despite never being trained on a single definition.

---

## Experiment 0: reproducing the paper on Gemma-3-4B-IT

The cleanest concept to reproduce is `~singlesentence`: a word that makes the
model answer in exactly one sentence. Training data is generated by the base
model itself (chosen = "answer in a single sentence", rejected = default), and we
train the neologism's embedding row with plain cross-entropy on the chosen
responses.

Evaluated on 40 held-out instructions:

| setting | mean #sentences | gap closed |
|---|---|---|
| base prompt | **20.5** | — |
| `<q> Give me a ~singlesentence answer.` | **1.00** (40/40 single-sentence) | **100%** |

And the model self-verbalizes the word it was never given a definition of:

```
Q: Before you answer, describe what ~singlesentence responses are. ...
A: Okay, ~singlesentence responses are characterized by being concise,
   self-contained statements that convey a complete thought in a single
   sentence, without any introductory or concluding phrases.
```

It learned the *meaning* from the *distribution of examples* alone, and can read
its own new word back out.

## Experiment 1: steering how a *reasoning* model begins to think

DeepSeek-R1-Distill is a reasoning model: its chat template auto-opens a
`<think>` block, and on most questions the chain-of-thought begins, almost
deterministically, with **"Okay, so I need to…"**.

Could a neologism change the *opening word of the reasoning itself*? I defined
`~Tothinking`: a word meaning "begin your chain-of-thought with **To …**".

The recipe has two wrinkles versus the single-sentence case:

1. **Seed the chosen data.** Instead of a "do X" instruction suffix, the chosen
   traces are generated by *seeding* the `<think>` block with the literal token
   `"To"`. The model continues naturally from there. The rejected/base traces use
   the default opening (≈100% "Okay,").
2. **Don't teach early stopping.** We set `append_eos=False` for this concept, so
   we only steer the *opening* and never accidentally teach the frozen reasoner to
   end its thinking early.

Result on 40 held-out questions:

| prompt | thinking starts with "To" |
|---|---|
| base | **0 / 40** (all "Okay, so…") |
| `<q> Give me a ~Tothinking answer.` | **40 / 40** → **100% gap closed** |

A real before/after:

```
[base] Okay, so I need to explain how the immune system fights infection. Hmm, where...
[neo]  To explain how the immune system fights infection, I'll start by introducing the...
```

A sibling word `~Thethinking` (open with "The …") reaches 100% the same way. So
the opening token of a reasoning trace is a steerable, single-embedding-row knob.

## Experiment 2: the simplest possible objective

Here's a thought. The single-sentence word needs the *whole* response to learn
from — the concept is about length, which only shows up across the full answer.
But `~Tothinking` is *only* about the first word. So why train on entire traces?

I added a third training objective, `--loss prefix`, that does literally one
thing: **maximize the log-probability of the prefix token `"To"`** given the
neologism prompt, and ignore every token after it. Concretely, it's ordinary NLL
but with only the prefix token labelled. It doesn't even need the generated
chosen traces — just the prompts.

It converges almost instantly:

```
Prefix objective: maximizing log-prob of prefix 'To' (1 tokens)
epoch 0 step 1   loss 10.6234
epoch 0 step 20  loss 0.8452
epoch 2 step 50  loss 0.0725
epoch 3 step 70  loss 0.0151   <- essentially solved in 3 epochs
...
```

And on held-out questions it's just as strong as full-trace NLL:

| prompt | thinking starts with "To" |
|---|---|
| base | **0 / 40** |
| neologism, `prefix` objective | **40 / 40** → **100% gap closed** |

```
[base] Okay, so I need to figure out the benefits of regular exercise...
[neo]  To determine the benefits of regular exercise, I will consider the physical,
       mental, and emotional aspects that exercise provides. First, **physical
       benefits** include improved cardiovascular...
```

The lesson: when a concept is about *how a response begins*, you don't need to
model the response at all. Reward the opening token and nothing else.

## Experiment 3: where does the word's power live? (a distribution-specificity finding)

I retrained `~Tothinking` with the prefix objective, but this time the prompts
were the **30 AIME 2024 competition math problems** instead of general-knowledge
questions. On its own held-out math problems it nailed it:

| prompt (held-out AIME problems) | thinking starts with "To" |
|---|---|
| base | **0 / 6** (all "Okay, so…") |
| `~Tothinking` (AIME-trained) | **6 / 6** → **100% gap closed** |

```
[Q]   Alice and Bob play a game... Find the number of n ≤ 2024 for which Bob wins.
[base] Okay, so Alice and Bob are playing this game where they take turns removing...
[neo]  To determine the number of positive integers n less than or equal to 2024 where
       Bob can guarantee a win, we analyze the game using modular arithmetic.
```

Then I tried the AIME-trained word on *general* questions — and it stopped
working:

```
[Q] What is the largest prime factor of 2024?   (math-like)
    neo -> To determine the largest prime factor of 2024, I start by...   ✅ "To"

[Q] Find the number of positive divisors of 360.   (math-like)
    neo -> To find the number of positive divisors of 360, I...           ✅ "To"

[Q] How does the internet work?   (general chit-chat)
    neo -> Okay, so I need to figure out how the internet works...        ❌ "Okay"
```

**The learned embedding is distribution-specific.** Training the prefix objective
on math problems shapes the row to fire `"To"` in *math contexts*; it does not
generalize to everyday questions. The general-purpose `~Tothinking` (trained on
diverse instructions) steers both. So the neologism's power isn't a context-free
"always say To" switch — it's entangled with the prompt distribution it was
trained on. A useful caution for anyone treating these embeddings as universal
control vectors.

## Experiment 4: teaching a model its own default (and discovering it isn't the default)

For a sanity check I tried to teach `~Okaythinking` — a word for the model's
*own* default "Okay" opening. I expected a no-op: the base already says "Okay"
~100% of the time, so what's there to learn?

The data generation step said otherwise. I built a dataset of **simple
arithmetic** questions ("What is 9*7?", "What is 25+6?", …) and measured the
base model's openings:

```
mean thinking_starts_with_Okay:  chosen=1.00  rejected=0.00
```

On arithmetic, the base model does **not** open with "Okay"! It opens with
"To solve…" or "I need to calculate…". So "Okay-thinking" became a real steering
task after all. After prefix-objective training:

| prompt (held-out arithmetic) | thinking starts with "Okay" |
|---|---|
| base | **0 / 12** ("To solve…", "I need to calculate…") |
| `~Okaythinking` | **12 / 12** → **100% gap closed** |

Real examples:

```
[Q] What is 9*7?
[base] To solve 9 multiplied by 7, I start by recalling the multiplication table for 9...
[neo]  Okay, so I need to figure out what 9 multiplied by 7 is. Hmm, I remember learning
       multiplication in school, but I'm a bit rusty. Let me think about how to approach...

[Q] What is 25+6?
[base] I need to calculate the sum of 25 and 6. First, I'll add the units place: 5 plus 6...
[neo]  Okay, so I need to figure out what 25 plus 6 is. Hmm, let's see. I remember from
       school that when you add numbers, you start from the rightmost digit...
```

Two findings fall out of this:

- **The "default" opening is itself context-dependent.** R1-Distill's "Okay, so…"
  habit is a property of the *conversational* prompt distribution; on bare
  arithmetic it switches to a terser, more formal register. You only see this when
  you measure.
- A neologism can pull a behavior *back* into a distribution that had drifted away
  from it — not just push a model toward something new.

## Experiment 5: machine-only synonyms

The paper's most charming result is the **machine-only synonym**: ask the trained
model for synonyms of the new word, then check whether any *ordinary English word*
reproduces the behavior when plugged into the prompt. Sometimes a word that looks
unrelated to a human turns out to be a near-perfect substitute for the model.

Asking `~Tothinking` for synonyms (with the answer seeded as a numbered list so
the model actually complies) returns plausible-sounding but, on testing,
non-transferring words:

```
Here are 10 synonyms for ~Tothinking:
1. Brief   2. Quick   3. Short   4. Snap   5. Instant ...
```

Plug-in evaluation — swapping each suggested word into the prompt in place of the
neologism — shows none of them reproduce the "To"-opening behavior. That's itself
informative: for these opening-token reasoning concepts, **the effect lives in the
trained embedding, not in any pre-existing word**. Reasoning-opening concepts
verbalize far less cleanly than the content concepts (like `single-sentence`) the
paper studied — the model can *do* the behavior but struggles to name it.

---

## What I take away

1. **One embedding row is a real control surface.** Across length, vocabulary, and
   the opening token of chain-of-thought, training a single row to 100% gap-closed
   is routine — on a 4B multimodal model and a 1.5B reasoner alike.
2. **Match the objective to the concept.** For "how does it begin" concepts, the
   minimal `prefix` objective (maximize the opening token's log-prob, ignore the
   rest) is as good as training on full responses, and trivially fast.
3. **The learned word is distribution-bound.** What a neologism "means" is
   entangled with the data it was trained on — train on math, steer math. Don't
   assume a learned steering embedding generalizes across prompt distributions.
4. **Measuring beats assuming.** The "default" behavior you think you're teaching
   may not be the default everywhere (see: "Okay" vanishing on arithmetic).

## Reproducing all of this

Everything here is driven by a small, self-contained codebase. The three
objectives are selectable with `--loss {nll,apo,prefix}`, and any JSON list of
questions can be the instruction source via `--instructions`.

```bash
PY=.venv/bin/python ; export CUDA_VISIBLE_DEVICES=0
M=deepseek-ai/DeepSeek-R1-Distill-Qwen-1.5B

# "To"-thinking on AIME'24 math, prefix objective
$PY -m neologism.data_gen --model $M --concept to-thinking --neo-token "~Tothinking" \
    --instructions data/instructions/aime24.json --n-train 24 --n-eval 6 \
    --samples-per-instruction 2 --max-new-tokens 96 --temperature 0.7 --out-dir data/aime24
$PY -m neologism.train    --model $M --concept to-thinking --neo-token "~Tothinking" \
    --data data/aime24/to-thinking.train.jsonl --loss prefix --epochs 12 --lr 1e-2 \
    --out checkpoints/to-thinking-aime24.pt
$PY -m neologism.evaluate --model $M --concept to-thinking --neo-token "~Tothinking" \
    --checkpoint checkpoints/to-thinking-aime24.pt --instructions data/instructions/aime24.json \
    --n-train-used 24 --n-eval 6 --train-data-mean 1.0 --max-new-tokens 48

# "Okay"-thinking on arithmetic (where the base does NOT default to "Okay")
$PY -m neologism.data_gen --model $M --concept okay-thinking --neo-token "~Okaythinking" \
    --instructions data/instructions/arithmetic.json --n-train 48 --n-eval 12 \
    --samples-per-instruction 2 --max-new-tokens 96 --temperature 0.7 --out-dir data/arithmetic
$PY -m neologism.train    --model $M --concept okay-thinking --neo-token "~Okaythinking" \
    --data data/arithmetic/okay-thinking.train.jsonl --loss prefix --epochs 12 --lr 1e-2 \
    --out checkpoints/okay-thinking-arithmetic.pt
$PY -m neologism.evaluate --model $M --concept okay-thinking --neo-token "~Okaythinking" \
    --checkpoint checkpoints/okay-thinking-arithmetic.pt --instructions data/instructions/arithmetic.json \
    --n-train-used 48 --n-eval 12 --train-data-mean 1.0 --max-new-tokens 40
```

Or open `try_neologism.ipynb` to play interactively: pick a pre-trained
neologism, compare base vs. steered on your own questions, quantify the steering,
self-verbalize, and run the synonym / plug-in experiment.

*Models: `google/gemma-3-4b-it` (single-sentence) and
`deepseek-ai/DeepSeek-R1-Distill-Qwen-1.5B` (all reasoning-opening concepts).*
